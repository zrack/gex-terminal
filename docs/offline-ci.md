# Offline CI Evidence

The [CI workflow](../.github/workflows/ci.yml) runs the same source tests, build,
installed-wheel smoke checks, and disposable upgrade/rollback/uninstall checks
on Ubuntu and macOS with Python 3.11 and 3.12. Matrix fail-fast is disabled so a
failure on one combination does not cancel the others. Application commands use
bundled synthetic data without live provider credentials. Dependency and build
tool installation can use the network.

Testing a runner is software verification for that run, not a supported-platform
promise, participant acceptance, live reliability, or predictive validation.
The existing release and publication process is unchanged. See
[First Run](first-run.md) for installation and [Contributing](../CONTRIBUTING.md)
for local build verification.

## Retained evidence

Every matrix job attempts collection even when a preceding check fails, and
uploads any safely completed collection, including partial results. The
artifact name identifies the runner, Python minor version, run ID,
and run attempt. GitHub retains it for 14 days, subject to repository policy.
The upload uses [GitHub's official artifact action](https://github.com/actions/upload-artifact).

The collector reads only the explicit `ARTIFACTS` mapping in
[`scripts/collect_ci_evidence.py`](../scripts/collect_ci_evidence.py) from the
job's disposable `runner.temp/gex-ci` directory. It stages:

- Demo/onboarding SVG previews and their provenance manifest.
- Numerical, replay, provider fixture, model, fault, performance, experiment,
  corpus, doctor and support reports generated by the offline checks.
- Selected synthetic research-pack manifests, integrity receipts, replay
  reports and terminal SVGs; these subsets are not portable complete packs.
- The successful disposable installation and recovery lifecycle report.

It does not recursively copy the workspace or research folders. Wheels,
environments, backups, raw command logs, `.env` files, and arbitrary extra files
are excluded. Input symlinks, directories in place of reports, empty files and
files above 2 MiB are rejected; total retained report bytes are capped at 16 MiB.
Staging must be new and outside the input directory. Only that staging directory
is uploaded, with hidden-file inclusion disabled.

The top-level `manifest.json` records:

- Checked-out source commit and whether tracked/untracked worktree changes
  existed; GitHub event SHA, repository, workflow, run, attempt, job and ref.
- Actual operating system, architecture and Python version.
- Each allowlisted file's producer, producer step outcome, retention status,
  byte count and SHA-256 when available.
- Missing/rejected files, failed/cancelled/skipped/unknown checks and size limits.

Only named GitHub identity fields and explicit step outcomes are read; the
environment and action output objects are never dumped. The collector trusts
these named outputs to come from the disposable synthetic workflow. It is not
a general-purpose secret scanner or redaction tool.

## Reading failures

A retained file is not by itself a passing check. Inspect its producer outcome
and the report's own result. If a smoke command fails partway through a step,
reports already written are retained, later outputs are marked missing, and
the step remains failed. The lifecycle verifier writes a report only on success;
a failed lifecycle therefore has an explicit failed step and missing report,
with detailed diagnostics in the GitHub job log. The collector writes its
manifest before exiting unsuccessfully for incomplete collection, and the
upload is still attempted. Upload requires the collector's completion marker;
an existing staging directory or a collector crash cannot authorize uploading
arbitrary leftover files. Collection cannot recover a job whose checkout or
Python runtime never became available, or a runner that was terminated.

For an inspectable local reproduction against a disposable synthetic output
directory, choose a fresh destination:

```bash
python scripts/collect_ci_evidence.py \
  --input-root /tmp/gex-ci \
  --output-dir /tmp/gex-ci-evidence \
  --step-outcomes '{"wheel":"failure","lifecycle":"skipped"}'
```

Unspecified check outcomes become `unknown`; missing GitHub identity fields are
`null` on local runs. An incomplete collection exits `1` after saving available
reports and the manifest. Do not point this command at customer or developer
research folders. For reproducible preview creation and visual acceptance, see
[Visual Assets](../assets/README.md).
